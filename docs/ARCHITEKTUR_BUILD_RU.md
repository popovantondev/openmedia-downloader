# Архитектура и сборка — простое объяснение

![OpenMedia Downloader в русской локализации](../assets/screenshots/ru/main-window.png)

## Из чего состоит программа

```text
Окно SwiftUI/AppKit
        ↓ действия и статусы
Swift OpenMediaCore (модели, очередь, процессы)
        ↓ аргументы и события JSON
Отдельный процесс Python-backend для задания
        ↓
yt-dlp · FFmpeg · Deno · источник медиа
```

Swift показывает окна, диалоги и статусы. `OpenMediaCore` управляет заданиями, ограничивает число одновременных загрузок и запускает отдельный backend-процесс для каждого задания. Python-backend проверяет ссылки, выбирает форматы и загружает или обрабатывает данные. yt-dlp взаимодействует с поддерживаемыми сервисами, FFmpeg обрабатывает медиа, а Deno предоставляет JavaScript-функции, которые могут понадобиться yt-dlp для некоторых источников.

Компоненты общаются через структурированные события. Поэтому окно может показывать названия и элементы плейлиста по мере их обнаружения, а тесты — безопасно подменять backend-процессы. У трансляции свой жизненный цикл: программа не выдаёт выдуманный конечный размер за размер обычной загрузки.

## Требования для разработки

- Mac с Apple Silicon и macOS 15 или новее.
- Xcode или Command Line Tools со Swift 6 и macOS SDK.
- Python 3 и пакеты, необходимые для разработки и тестов backend.
- FFmpeg/ffprobe и yt-dlp для локальных интеграционных проверок медиа.

В публичном пакете исходников намеренно нет готовых медиапрограмм, Python runtime и полных архивов исходников сторонних компонентов. Поэтому сейчас из него нельзя воспроизводимо собрать полный пакет приложения. Проверка лицензий и происхождения компонентов ещё не завершена; см. [права и статус выпуска](RIGHTS_RU.md) и [обзор сторонних компонентов](THIRD_PARTY_OVERVIEW_RU.md).

## Разработка Swift-компонентов

В папке проекта Swift Package Manager может собрать или протестировать Swift-компоненты:

```sh
swift test
swift build
```

Эти команды собирают или тестируют только Swift-компоненты. Они не создают полное приложение macOS и не загружают реальные медиа. В публичном пакете нет одобренной к распространению runtime-сборки backend. Сетевые проверки проводятся отдельно и требуют подходящих тестовых медиа и инструментов.
